# Quick I Ching V2.1 Remediation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` task-by-task. Every behavior change follows RED → GREEN → REFACTOR.

**Goal:** Deliver the approved V2.1 remediation as six independently reviewable, stacked pull requests with executable verification.

**Architecture:** Thin Server Actions call focused application services. Services enforce lifecycle and authorization invariants through repository ports. PostgreSQL is the production source of truth; memory implementations are explicit local/test adapters. External providers are selected only by validated runtime configuration.

**Tech Stack:** Next.js 15, React 19, TypeScript, Zod, Vitest, Drizzle ORM, PostgreSQL, Better Auth, Creem, Vercel Workflow, structured AI output.

- Keep only `PRD.md` and `技术设计文档.md` under `docs/`.
- Preserve all PRD requirement IDs and independent state machines.
- Never expose result fields before committed reveal authorization.
- Never trust browser state for server-owned facts.
- Validate all external input and generated output.
- Never silently select a development adapter in production.
- Never fabricate credentials, licensed content, provider approval, or live smoke-test evidence.
- Run lint, typecheck, tests, and build through GitHub Actions before creating each draft PR.
