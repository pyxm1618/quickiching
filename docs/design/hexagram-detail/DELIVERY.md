The follow-up only changes this English view's image delivery:

- All 15 approved PNG originals and their source hashes remain intact. No artwork was generated, reconstructed, cropped from the design screenshot, or baked with page text.
- `scripts/encode-hexagram-detail-assets.mjs` creates 38 explicit resized delivery encodings with installed Sharp 0.35.4/libheif 1.23.2. `delivery-assets.json` records every approved source SHA, output SHA, dimensions, format, encoder options and status. **38 = pass 38 + deferred 0 + reject 0 + unknown 0**. All 38 are actually decoded and checked; browser HTTP hashes also match.
- General AVIF encodings use quality 65, effort 6, 4:4:4. Mobile scene and small Taiji encodings use quality 30; mobile Taiji remains under the pre-existing 0.22 CSS opacity. Desktop paper uses WebP quality 75; mobile paper quality 50 at the same 627/1254 density dimensions. These are lossy delivery versions, never labelled lossless or pixel-identical.
- Both repeating edges use full-size **lossless WebP**, verified against source for exact alpha and every RGBA pixel with nonzero alpha. RGB under fully transparent pixels may be canonicalized by WebP and is invisible. Cap + repeat + cap structure, cap aspect ratios and repeat scale are unchanged.
- Density-aware CSS and responsive native image sources avoid sending desktop decoration sizes to narrow screens. Offscreen bottom roll/branch and pine load via real native lazy images, retaining intrinsic geometry. Browser QA scrolls to each and waits for actual image decoding before full-page screenshots.
- The actual paper background is preloaded, with matching desktop/mobile media and source sets. Visible cap, top-roll, branch and Taiji images are eager native images with explicit low fetch priority. Scene and repeat hints also request low priority, allowing paper and text to win scheduling without hiding or delaying visible artwork. Narrow-screen bokeh uses an aspect-preserving 640px derivative; wider screens retain their existing density choices. The paper remains the real LCP element; it was not moved or hidden to evade measurement.
- No Next config, global optimizer setting, dependency, API, data, body text, font size, component spacing, or performance assertion/threshold changed. The Lighthouse gate only adds English image/font/LCP diagnostic logs, after collection and before the same assertions. The fixed scene moved from the body background into a scoped fixed pseudo-element so it can inherit route-specific responsive delivery variables; its viewport positioning is preserved.
