# GA4 Basic Consent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add consent-gated GA4 measurement that never loads Google tags before explicit acceptance and never accepts sensitive free-form product data.

**Architecture:** A pure consent-policy module owns cookie and identifier rules, a client consent controller owns UI and lifecycle, and a small Google tag component loads gtag only after `granted`. A separate event boundary enforces an allowlist and token-only string values.

**Tech Stack:** Next.js 15 App Router, React 19, TypeScript strict, Vitest node environment, Bun.

## Global Constraints

- Base all work on `agent/rename-quick-i-ching` commit `7c043b62e6aa5e1a9283701c467bae5200508b41`.
- Do not add an analytics dependency; use the existing Next.js runtime and `next/script`.
- Load GA4 only when `NODE_ENV=production`, the measurement ID is valid, and consent is `granted`.
- Keep `ad_storage`, `ad_user_data`, and `ad_personalization` denied.
- Never send question text, context, email, reading/report content, secrets, or payment details.
- Do not add manual page-view events that duplicate Enhanced Measurement.
